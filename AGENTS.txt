freebsd-userland-zos-port (fsh) -- working notes for automated contributors

Project rules are in README.md and docs/direction.md. This file records
how to work here without wasting cycles, and the mistakes that have
already cost time. Add a line every time something bites.


1. WHAT THIS IS

oksh 7.9 (pdksh lineage, ksh88) ported to z/OS. The base is upstream
oksh with a small, documented set of edits; do not restructure it.
Every edit to a base file is recorded in docs/port.md in the same
commit. The language is a closed set (docs/language.md) -- do not add a
construct because it is convenient; add it to the document first.

Companion repos, do not confuse them:
  ~/src/oksh   upstream oksh + the zos-spawn branch this tree came from
  ~/src/zash   the ash reference implementation, separate remote,
               NOT vendored here
  ~/src/freebsd-userland-zos-port-src
               the FreeBSD userland port for z/OS; its bin/sh is the
               only vendored benchmark reference (vendor/freebsd-sh)
  ~/src/zrx    unrelated (REXX interpreter)

The oksh, dash and ksh93 vendor trees were removed on 2026-11-07.
The benchmark had one question -- how fast is fsh against the
alternatives? -- and it answered it: FreeBSD sh was fastest on the
CPU-bound workloads. Keep the oksh source pin for lineage, not a
checkout. Do not re-add the retired vendor trees without a new
measurement that needs them.


2. BUILD AND TEST

  git submodule update --init --recursive                  # once after clone
  ./configure --release && cmake --build build -j8        # Linux
  ./build/fsh -c 'print hello'
  ctest --test-dir build --output-on-failure               # 4 smoke tests
  cmake --build build --target bench                       # fsh vs FreeBSD sh

  # z/OS (ibm-clang64 found automatically; cmake+ninja from zopen)
  bash ./configure --zos --release && cmake --build build -j8
  ./build/fsh -c 'print hello'
  ctest --test-dir build --output-on-failure   # 4/4 on z/OS too

The z/OS build compiles, links, runs and passes ctest as of
2026-11-06; docs/port.md records every fix (P6-P27). Anything not yet
RUN on z/OS is still a claim from documentation: mark it VERIFY in the
source comment, as zos_spawn.c does. Runtime job control, co-processes,
line editing and the spawnp path are all in that category.

BEWARE the checks cache. cmake/checks.cmake probes are sticky; if a
probe is changed, `rm -rf build` before reconfiguring, or a stale answer
from the old probe survives.


2a. Z/OS FEATURE MACROS -- CHECK THIS FIRST

z/OS headers gate interfaces on a stack of macros, and each hides a
different set. A function "missing" on z/OS is usually a missing macro.

  _ALL_SOURCE        the broad switch
  _XPLATFORM_SOURCE  BSD/X-Open: flock(), timeradd()/timersub()
  _OPEN_SYS          z/OS UNIX: setgroups()
  _OPEN_SYS_FILE_EXT extended file data: struct stat's st_tag
                     (ft_ccsid, ft_txtflag), fcntl()'s F_SETTAG and
                     F_CONTROL_CVT
  _POSIX_C_SOURCE=200809L  POSIX.1-2008: strsignal()

  NOT _UNIX03_SOURCE. It switches the headers to the __-prefixed LE
  entry points (__sysconf, __fopen_ascii), and the binder cannot
  resolve those in a statically linked program: IEW2456E, exit 12.
  _ALL_SOURCE already gives setenv() under its non-POSIX name.

The build passes all five (CMakeLists.txt, FSH_ZOS) and the probes
pass the same set (cmake/checks.cmake). If you add a probe, add the
macros to both or the probe lies. Confirm against the CRTL reference in
~/docs/mainframe/txt/zos-c-runtime-library.txt, which states the exact
`#define` line each function needs -- do not guess, the docs are local.

Features z/OS genuinely does not have, verified in those docs:
  <sys/param.h>, <paths.h>, confstr()'s _PATH_* set, WCOREDUMP(),
  timerclear() (but timeradd/timersub exist), struct stat's st_mtim
  (only st_mtime), the sig_t typedef, _POSIX_VDISABLE.


3. CHARACTER SET -- THE BIG ONE

z/OS is EBCDIC (IBM-1047). Linux is ASCII/UTF-8. Both must work.

  - 'a'..'z' are NOT contiguous in EBCDIC; '0'..'9' ARE.
  - In EBCDIC letters sort BEFORE digits; ASCII sorts digits first.
  - char is UNSIGNED on z/OS. Index tables with (unsigned char)c.
  - Never write a raw control byte as 'X'; use "\x41" style escapes.
  - A file's character set is its chtag, not its bytes. Generated or
    created files need a tag; see zash's sys_zos.c for the measured
    behaviour (_ENCODE_FILE_NEW, IBM-1047 for pipes, not ISO8859-1;
    zoslib's ISO8859-1 choice leaves EBCDIC readers seeing ASCII).
  - zash's word representation (raw text + parallel origin-mark array)
    avoids in-band control bytes entirely. oksh uses in-band bytes
    (QUOTE etc.); that is the main EBCDIC risk in this base.
  - Do not use $'\r' in scripts that must run under the system
    /bin/sh on z/OS -- it has no $'...' at all.


4. C PORTABILITY

  - C99/C11, no GNU extensions. Open XL C/C++ 2.1 is clang-based.
  - oksh is old code: K&R-adjacent idioms, implicit int assumptions in
    places. Fix with the full warning set, not bare clang.
  - z/OS specifics live in zos_spawn.c and (to be added)
    zos_builtins.c / sys_zos.c, behind __MVS__ / HAVE_ZOS_SPAWN.

z/OS hazards:
  - fork() copies the whole address space; use spawnp() for external
    commands. Pipelines/coproc/comsub stay on fork (spawn children
    cannot close sibling pipe fds).
  - isatty()/tcgetattr() do not work under TSO (no controlling
    terminal). OMVS is line mode only.
  - A child forked from a threaded process may only call
    async-signal-safe functions before exec. The shell is single
    threaded; keep it so.
  - MVS allocations and data set opens are NOT inherited across
    fork/exec.

2b. THINGS THAT COST A SESSION ON 2026-11-06

  - CMAKE_TOOLCHAIN_FILE is read at project() time, BEFORE
    CMakeLists.txt declares its options. A toolchain test of
    if(FSH_EDITOR) is therefore always false. Ask
    if(DEFINED ...) and default to the option's declared value.
  - check_function_exists() runs only if its result variable is
    UNDEFINED (`if(NOT DEFINED ...)`). Pre-setting HAVE_x to 0 to guard
    against a stale cache skips the probe, and a skip is
    indistinguishable from "not found". unset() it instead.
  - "the symbol links" and "a header declares it" are different
    questions. zoslib supplies symbols the z/OS headers never declare,
    so every HAVE_x that links also needs HAVE_x_DECL.
  - /bin/sh cannot run this repo's scripts ("FSUM7332 syntax error:
    got ("); it has no $( ). Use bash or oksh. Tagging the file UTF-8
    does not help, and _BPXK_AUTOCVT does not change it.
  - **A tagged script does not run.** fsh executes only UNTAGGED
    scripts on z/OS; a tagged one is converted EBCDIC to ASCII on read
    while the literals stay EBCDIC, so the newline is not a separator
    and the parse collapses (docs/port.md P29). Every tests/*.sh is
    UTF-8-tagged, so the script suite cannot pass on z/OS. Do not
    re-tag the tests to hide it; fix the conversion.
  - libncursesw.a does not bind alone: it needs zoslib
    (-lzoslib -lzoslib-supp). The ncurses pkg-config Libs line says so;
    the toolchain finds it.
  - Adding the PARENT of include/ncursesw to the include path pulls in
    zopen's entire shared header tree, which shadows <sys/time.h>,
    <sys/param.h> and friends. Expose ncurses through the one-entry
    shim directory instead.
  - fsh writes IBM-1047; zopen's utilities write ASCII when the
    destination is untagged. A redirect that mixes builtin and external
    output mixes encodings. Do not "fix" the shell's encoding.
  - The CMake cache is stickier than it looks: a changed probe, a
    changed find_program, or a changed toolchain needs a fresh build
    dir, not just a rebuild. Two sessions were spent on stale caches.
  - **The z/OS shell does not automatically convert your text.** `od
    -c`, `cat`, `wc -l` and `grep` read IBM-1047 files as bytes: `wc
    -l` reports 0 lines for a 39,000-line source file (EBCDIC newline
    is 0x15, not 0x0A), and `cat` echoes EBCDIC that arrives as `?.`
    noise. Do not conclude a file is empty or corrupt from that. Pipe
    through `base64` to get text across ssh intact:
    `ssh cbt 'base64 < file' | base64 -d`.
  - Do not hand-edit sources in place on the host with `awk`/`sed`:
    the z/OS tools mangle long lines (FSUM9393, limit 20,000) and a
    half-written file is left behind. Edit locally, `scp`, then
    `chtag -tc UTF-8` if the copy lost its tag. An untagged source
    file fails the compile with `EDC5122I Input/output error`.
  - **A stdout redirect on z/OS may be ASCII or EBCDIC depending on
    the destination's tag**, so "decoding" the output of a test can
    turn a correct result into noise. Pre-tag the file (`: > f;
    chtag -tc IBM-1047 f`) exactly as tests/run.sh does.

6. RECURRING MISTAKES

  - Claiming a measurement without taking it. budget.md numbers are
    measured; "editor code 5,715" was written from memory once and was
    wrong by 9 lines. Measure, then write.
  - Confusing oksh, pdksh and AT&T ksh88 when describing lineage.
  - Writing ${v/pat/rep} in a test: pdksh does not have it. It is a
    planned addition, not existing behaviour.
  - Editing a file in the build tree and forgetting that `configure`
    regenerates the Makefile; object lists live there, and a new .c
    needs adding to configure's OBJS or it is never compiled.
  - Building in /tmp with bare clang and calling it done.
  - Trusting a stale binary: recompile in the same command line as the
    run.
  - Re-adding the oksh, dash or ksh93 vendor trees. The benchmark
    settled that question: FreeBSD sh was fastest, so only it remains
    as `vendor/freebsd-sh` (a submodule). A new reference shell needs a
    new question, not nostalgia.


7. Z/OS FACTS WORTH KEEPING

  - Profiles: /etc/profile -> $HOME/.profile -> $ENV. `sh -L` is a
    login shell on z/OS (uppercase L).
  - No ksh is installed on z/OS: only the System V sh and tcsh.
  - spawnp() (BPX1SPN) never forks. _BPX_SHAREAS=YES makes fork()
    produce a shared daughter. SPAWN_SETGROUP|SPAWN_NEWPGROUP gives
    race-free process-group creation with ctlttyfd.
  - chcp changes the terminal conversion; not under OMVS.
  - zopen provides make, bash, gawk, ncurses (widec), but not libedit.
  - Reference docs on this machine:
      /home/skurtz/docs/mainframe/txt/zos-c-runtime-library.txt
      /home/skurtz/docs/mainframe/txt/zos-unix-command-reference-bpxa500_v3r2.txt
