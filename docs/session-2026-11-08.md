## How the merge was done

The libedit repository had one commit. Its history was rebased under
`contrib/libedit` so the files had always lived at the FreeBSD path:

```sh
git remote add libedit-import ~/src/freebsd-userland-zos-port-libedit
git fetch libedit-import main:refs/heads/import-libedit
git filter-branch --tree-filter '
    mkdir -p contrib/libedit &&
    find . -mindepth 1 -maxdepth 1 ! -name contrib ! -name .git \
        -exec mv {} contrib/libedit/ \;
' import-libedit
git merge --allow-unrelated-histories --no-ff import-libedit
```

`git log --follow` on `contrib/libedit/el.c` therefore reaches the
libedit import. The libedit repository's own `README.md`, `UPSTREAM`
and `.gitignore` were folded into the top-level files; no upstream
source file was changed.

`lib/libedit` was added from the same FreeBSD pin. It is the canonical
FreeBSD build location for libedit, next to the `contrib` import. The
Linux adapter and fsh's CMake build still build out of tree and do not
use these FreeBSD Makefiles.

The repository was renamed on GitHub with `gh repo rename`, the tag
`freebsd-15.1.0` was moved to the merged commit `ba31715`, and the
merged `main` was pushed.

## Verification on z/OS

The merged repository was cloned on the CBT z/OS host (`ssh cbt`) into
`~/src/freebsd-userland-zos`, and the superproject into `~/src/zksh`
with `vendor/freebsd` checked out at `ba31715`.

Build after the fixes logged in `docs/port.md` (2026-11-08):

```sh
export PATH=/usr/local/zopen/usr/local/bin:$PATH
cd ~/src/zksh
bash ./configure --zos --release --ninja --build-dir=build-zos
cmake --build build-zos -j4
```

Result: 79 targets built, a 3,813,376-byte XPLINK binary, no binder
errors. `./build-zos/fsh -c 'echo hello'` writes the EBCDIC bytes
`88 85 93 93 96 15` when the destination is IBM-1047-tagged, and an
untagged IBM-1047 script with a `for` loop runs with status 0.

`ctest` is not green on z/OS: the smoke tests compare EBCDIC output
against ASCII regexes, and `tests/harness` plus `tests/*.sh` are
UTF-8-tagged. That is the pre-existing P29 script-conversion problem,
independent of the repository merge. The full list of z/OS build
fixes (libedit config, generator encodings, header shims, libc gaps,
z/OS link items, `zos_autocvt_off`) is in `docs/port.md` under
"2026-11-08: the FreeBSD bin/sh base builds on z/OS".
